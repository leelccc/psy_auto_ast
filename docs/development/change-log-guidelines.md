# 开发变更记录规范

日期：2026-06-15

后续每个功能批次、缺陷修复或重要配置变更完成后，都必须同步更新项目记录，不能只在聊天中说明。

## 必须记录的内容

每条记录至少包含：

1. **改动目标**：本次解决什么用户问题或技术问题。
2. **改动点**：新增、修改或删除了哪些页面、接口、服务、数据字段或配置。
3. **实现方法**：前端、后端、数据库、MinIO、AI 服务分别如何处理，责任边界是什么。
4. **数据与接口影响**：是否改变请求参数、响应字段、持久化结构、权限或生命周期规则。
5. **异常与边界**：失败状态、过期状态、权限不足、空数据、重复提交等如何处理。
6. **测试与验证**：新增哪些测试，自动化测试数量，是否完成浏览器或真实服务验证。
7. **已知限制和后续事项**：本次未覆盖的内容、暂缓事项和需要继续讨论的问题。
8. **运行状态**：测试结束后哪些服务保持运行，哪些临时服务已经停止。

## 记录位置

- `progress.md`：按日期记录已完成工作、实现方法和验证结果。
- `task_plan.md`：更新阶段任务状态、长期决策和下一步工作。
- `docs/prd/session-memory.md`：记录长期有效的产品边界、架构决策和协作约定。
- `docs/backend/implementation-notes.md`：记录后端接口、任务、存储、权限和生命周期实现约束。
- 专项设计或复杂改动：在 `docs/plans/` 或 `docs/superpowers/` 下保留独立设计和实施方案。

## 记录时机

- 开始开发前：确认目标、职责边界和影响范围。
- 实现过程中：记录新发现的风险、异常和待讨论事项。
- 测试完成后：立即更新改动点、实现方法、测试结果和已知限制。
- 会话结束前：确认进度记录与实际代码状态一致。
