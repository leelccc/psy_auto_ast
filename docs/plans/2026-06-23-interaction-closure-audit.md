# 交互逻辑闭环审计

日期：2026-06-23  
范围：`apps/mobile/App.tsx` 当前移动端主流程  
目标：逐项判断每个功能是否需要逻辑闭环，并确认当前闭环是否完整。

## 1. 闭环判断标准

一个交互如果涉及以下任一动作，就必须闭环：

- 创建：新建账号、档案、记录、会话、资料。
- 修改：编辑摘要、标签、转写、章节、报告、设置。
- 删除：删除记录、资料、会话、账号。
- 异步任务：录音保存、归档、AI 生成、重新生成、上传、导出、下载、同步日历。
- 授权：档案访问密码、长期保存授权、AI 督导资料授权。
- 导航上下文：从哪个页面进入，完成后应回到合理位置。

完整闭环至少包含：

1. 可见入口：用户知道此按钮/区域能做什么。
2. 前置条件：条件不足时说明缺什么，而不是静默失败。
3. 执行状态：异步动作有“进行中/禁用重复触发”。
4. 成功反馈：状态、列表、页面或提示可核对。
5. 失败恢复：失败后输入不丢、页面不误关闭、可重试。
6. 后果说明：删除、覆盖、授权、同步这类高风险动作说明影响。
7. 返回路径：完成后回到用户发起任务的上下文。

## 3. 尚未完全闭合的重点缺口

### P0：需要尽快补齐

### P1：建议继续修

| 功能 | 缺口 | 建议 |
|---|---|---|
| 标签增删 | 单次记录编辑中的标签删除 / 添加直接触发后端更新，但没有单项保存中状态 | 给标签操作增加轻量 pending，失败时提示并保留输入 |

## 4. 总结

当前版本的主业务闭环已经基本成立：

- 录音可以从开始、保存、归档、生成、编辑、下载走完。
- 档案可以创建、解锁、增删单次记录、上传材料、生成记录。
- 个案报告可以选择资料、覆盖草稿、编辑、保存正式版、下载、授权。
- 隐私中心可以查看到期资料、授权、撤回、删除。
- 智能督导可以创建会话、添加资料、发送、显示引用。
- 日程和安全设置有保存中状态和风险提示。

剩余问题主要不是“走不通”，而是更细的闭环质量：

- 个别轻量动作缺按钮级 pending。
- 下载和授权类动作还可以统一防重复点击。
- 系统日历和 AI 取消生成涉及产品 / 后端策略，需要确认后再闭合。

真实浏览器验证中发现并修复的问题：

- 问题：静态 Web 预览从 `http://127.0.0.1:19006` 请求后端 `http://127.0.0.1:8000` 时被 CORS 拦截，导致登录不能闭环。

- 防回归：新增后端 preflight 测试，确认 `OPTIONS /api/v1/auth/login` 对 `http://127.0.0.1:19006` 返回正确 CORS 头。

仍未逐项真实点击的内容：

- 没有把矩阵里每一个按钮都用浏览器自动化逐项点击一遍。
- 当前“全部闭环”结论由三部分组成：代码审计 + 自动化测试 + 关键真实链路浏览器验证。
- 要达到严格意义的“每个按钮真实闭环”，还需要继续写一套端到端脚本，覆盖归档、档案、记录、报告、隐私、督导、日程、安全设置等完整路径。
