# 前端 UI 系统审计与优化设计

## 目标

在不重做产品信息架构的前提下，让页面在 320px 手机、常规手机、平板和桌面 Web 上保持稳定；减少解释卡片造成的视觉负担；统一高频输入的前后端约束。

## 设计方向

- 延续现有暖米色与陶土色品牌，不引入新的视觉语言。
- 采用清晰的主次层级、44–48px 触控目标和克制阴影。
- 页面正文仍以手机宽度为主；平板和桌面居中呈现，避免表单无限拉宽。
- 信息提示按重要性分级，不把所有说明一律隐藏进气泡。

## 信息分级

1. **始终可见**：错误、危机提示、删除后果、保存期限、当前状态和需要用户作决定的信息。
2. **摘要可见、详情展开**：隐私保存规则、数据使用范围等重要但较长的说明。
3. **按需展开**：编号格式、字段填写示例等低频帮助。
4. **不使用仅悬停 Tooltip**：产品以触屏为主，帮助信息必须可点击、可聚焦，并在展开后进入正常文档流。

## 响应式与长文本规则

- 共享横向布局中的正文容器必须设置 `minWidth: 0`，标题与次要文本允许收缩。
- 标签组和筛选项允许换行；状态徽章、编辑入口等操作控件保持完整。
- 列表标题优先占用剩余空间；需要完整阅读的正文自然换行，索引性文本才做截断。
- 320px 宽度不得出现页面级横向滚动；390px 与 768px 需保持一致的信息顺序和可操作性。

## 输入契约

| 字段 | 前端 | 后端 |
|---|---:|---:|
| 邮箱 | 254 | 254 |
| 密码 | 6–128 | 注册/重置 6–128，登录最长 128 |
| 显示名/档案名 | 80 | 80 |
| 档案编号 | 12 | 12 |
| 约定次数 | 0–999 | 0–999 |
| 自定义频率 | 80 | metadata.frequency 80 |
| 首访主诉 | 2000 | metadata.first_visit_complaint 2000 |
| 档案备注 | 4000 | 4000 |
| 历程摘要 | 4000 | 4000 |
| 历程标签 | 最多 4 个，每个 24 | 最多 4 个，每个 24 |

## 本批实现

- 新增触屏友好的 `InfoDisclosure`，用于编号规则和保存规则。
- 档案创建页由长说明卡改为“短摘要常显 + 详情按需展开”。
- 共享列表正文增加收缩边界，区块标题与长文本不再挤压右侧操作。
- 为认证、档案创建/编辑、历程创建/编辑与标签补齐前端长度限制。
- 为认证、档案和历程模型补齐对应后端边界。

## 后续优先级

1. 用同一信息分级规则逐页收口录音、报告、隐私中心中的重复说明卡。
2. 将散落的颜色、边框、提示卡和按钮变体收敛到主题令牌与共享组件。
3. 为所有剩余自由文本字段建立同一份字段契约，并补充计数器或临界提示。
4. 在 Android/iOS 真机验证键盘避让、动态字体和系统缩放；Web 通过不代表原生端验收完成。
