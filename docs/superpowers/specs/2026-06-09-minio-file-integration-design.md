# MinIO 文件集成设计

日期：2026-06-09

## 目标

用户上传的录音、量表、作业、其他资料及法律/伦理文件最终保存在 MinIO。下载时获取原文件，不根据页面元数据生成替代文件。

本轮只完成前端接口边界和数据模型预留，不连接真实后端或 MinIO。后端文件接口在后续后端实施阶段统一完成。

## 前端边界

前端新增独立文件服务接口，页面组件不直接拼接 MinIO URL，也不依赖具体对象存储实现。

核心能力：

- 创建上传任务并取得短期预签名上传信息。
- 将本地文件上传到预签名地址。
- 通知后端上传完成。
- 按 `fileId` 请求短期下载地址。
- 替换和删除已上传文件。

前端文件记录至少保留：

- `fileId`
- `filename`
- `mimeType`
- `sizeBytes`
- `uploadStatus`
- `sourceKind`

前端不保存 MinIO `storageKey`，也不长期保存预签名 URL。预签名地址只在当前上传或下载动作中使用。

## 后端接口契约

后续后端实施以下接口：

1. `POST /api/v1/files`
   创建文件记录，返回 `file_id`、预签名 PUT URL 和必要请求头。
2. `POST /api/v1/files/{file_id}/complete`
   校验 MinIO 对象存在并确认上传完成。
3. `GET /api/v1/files/{file_id}/download-url`
   校验用户归属后返回短期预签名 GET URL。
4. `DELETE /api/v1/files/{file_id}`
   删除 MinIO 对象并标记文件已销毁。
5. 附件替换接口
   新文件完成上传后切换附件引用，再删除旧对象。

## 数据流

### 上传

```text
选择本地文件
-> 前端创建上传任务
-> 后端返回预签名 PUT URL
-> 前端直传 MinIO
-> 前端通知后端上传完成
-> 页面保存 fileId 并刷新附件列表
```

### 下载

```text
用户点击下载
-> 前端按 fileId 请求下载地址
-> 后端校验登录用户和文件归属
-> 后端返回短期预签名 GET URL
-> 前端打开或下载原文件
```

## 替换与删除

- 替换采用“先上传新文件、再切换引用、最后删除旧文件”的顺序。
- 上传或切换失败时保留旧文件。
- 删除由后端执行 MinIO 对象删除和生命周期状态更新。
- MinIO bucket 保持私有，前端不能持有永久公开地址。

## 与生成文档的边界

- 用户上传的文件通过 `fileId` 下载 MinIO 中的原始字节。
- 咨询记录、督导记录、个案报告和录音纪要等生成文档继续使用生成/导出流程。
- 两类下载不得共用“根据可见元数据生成 PDF 副本”的逻辑。

## 本轮实施范围

- 新增可测试的前端文件服务接口定义。
- 为 session material 和法律/伦理文件预留 `fileId`、MIME、大小和上传状态。
- 文件预览页根据是否存在 `fileId` 决定原文件下载是否可用。
- 提供当前原型使用的未连接实现，明确返回“等待后端文件服务”，不生成假文件。
- 保持现有生成文档 PDF 下载功能不变。

## 后续后端实施范围

- MinIO 客户端与配置。
- 预签名 PUT/GET。
- 对象存在性与大小/MIME 校验。
- 用户隔离、附件关联、替换、删除和 14 天生命周期。
- 使用可注入存储适配器编写单元测试，并使用本地 MinIO 做集成验证。

## 验证

- 前端单元测试覆盖文件记录映射、下载可用性和未连接状态。
- TypeScript 类型检查通过。
- Expo Web 构建通过。
- 回归确认生成文档仍可下载，上传文件不再生成元数据 PDF 副本。
